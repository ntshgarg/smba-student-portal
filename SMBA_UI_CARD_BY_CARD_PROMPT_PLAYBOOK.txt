Purpose
-------
This file is the complete prompt sequence for refining SMBA one destination
family at a time, approving each direction before implementation, freezing
finished work, and redesigning the dashboard cards only after their
destinations are complete.

This programme deliberately separates:

1. Destination-page work: the pages reached from dashboard cards.
2. Dashboard-card work: the compact entries on /coach and /player.
3. Shared-component consolidation: only after repeated patterns are proven.

The objective is consistency, clarity and lower cognitive load. It is not to
make every specialist workflow look identical, invent a new design system, or
turn SMBA into generic administration software.


HOW TO USE THIS FILE
======================================================================

1. Start a clean chat for this redesign programme.
2. Submit Prompt 00 first. Do not submit the whole file at once.
3. Submit one numbered prompt at a time.
4. At every APPROVAL GATE, review the result and explicitly approve or amend it.
5. Never move from audit to implementation in one instruction.
6. Complete and freeze one destination family before beginning the next.
7. Use disposable database clones for all browser automation.
8. Do not let automation write to any canonical database.
9. Do not redesign dashboard cards until the destination-page programme is
   complete.
10. If a change affects domain rules, routes, persistence, authorization or
    accounting, stop. That is outside this visual programme.

STANDARD EVIDENCE AND APPROVAL CONTRACT
======================================================================

Every Audit prompt inherits:

- Read source, directly relevant tests, .21st context and frozen decisions.
- Run 21st review normally and with JSON output over relevant UI paths.
- Never use 21st review --fix during a read-only audit.
- Use fresh runtime evidence, not screenshots from an older implementation.
- Give every finding a stable ID.
- Include category, severity, route and full query, state, role, data profile,
  viewport, screenshot, source file/line, contract clause, reproduction,
  expected/actual result and confidence.
- Provide a coverage ledger and clearly mark anything NOT RUN or unproven.
- A visual claim without a matching route/state/profile/viewport capture is not
  accepted evidence.
- Typography inventory means computed role, family, size, weight, line height,
  case and tracking—not merely the CSS selector name.
- Copy classification must explain what user decision, warning, recovery or
  business rule the text supports.

Every Explore prompt inherits:

- Read accepted finding IDs and current .21st context.
- Search 21st first and cite project/catalog references used.
- Keep prototypes outside production paths.
- Produce three directions differing on at least two structural axes.
- Show comparable real content/states at 390×844 and 1440×900 and explicit
  behavior for 320×568, 844×390 and 1024×768.
- Direction previews are not implementation approval.

Every Final Specification inherits:

- Route-by-route heading tree and exact copy.
- Widths, spacing roles and action order.
- Empty/loading/unavailable/validation/success/failure states.
- Mobile, landscape, tablet and desktop rules.
- Keyboard, focus, screen-reader and reduced-motion behavior.
- Preserved domain/route/URL rules, accepted exceptions and exact file scope.

Every Build prompt inherits:

- Inspect worktree and preserve unrelated changes.
- State exact file scope before editing and stop on ambiguous overlap.
- Search 21st first, reuse installed SMBA primitives and add no dependency
  without explicit approval.
- Apply only the approved specification; do not improvise polish.
- Run TypeScript, ESLint, relevant focused tests, production build and 21st
  review on changed paths.
- Any command capable of opening application data must use the verified clone.
- Report each command and PASS, FAIL, NOT RUN or BLOCKED honestly.

Every Verification prompt inherits:

- Fetch the latest Web Interface Guidelines at verification time.
- Use native Python Playwright; inspect the provided server helper with --help
  before invoking it; use headless Chromium and wait for network idle.
- Reconcile the DOM/selectors before scripted interactions and always close the
  browser.
- Capture console messages, page errors, request failures and HTTP errors.
- Test Edge and Stress clones unless a named state requires a smaller derived
  disposable clone.
- For a downloaded PDF verify the browser download event, response status,
  safe filename, MIME type and non-zero bytes—not merely the button click.
- Loading/failure evidence must be deterministic, using safe fixture setup or
  controlled interception after reconnaissance.
- Verification is read-only with respect to product source.

Every Correction prompt inherits:

- Only exact defect IDs approved by the user may change code.
- Reproduce first; map each edit one-to-one to evidence.
- Add focused regression coverage where practical.
- Rerun failed scenarios before cumulative affected-consumer regression.
- Do not bundle preference, cleanup, abstraction or copy edits.

Every Freeze prompt inherits:

- Record decision ID, approval date, exact routes/surfaces, contract version,
  direction, responsive/state/accessibility rules, accepted exceptions,
  verification manifest, screenshot references, source revision/dirty note,
  status and allowed future-change reasons.
- Validate .21st/design.json.
- Modify design context only; do not modify product source.
- Preserve history and supersede rather than silently deleting an old decision.
